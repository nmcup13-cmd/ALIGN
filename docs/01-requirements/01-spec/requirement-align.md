# Requirement: ระบบติดตามความสอดคล้อง CLO/PLO (ALIGN)

## บริบท (Background)

อาจารย์ผู้สอนต้องจัดทำหลักฐานความสอดคล้องระหว่างการสอน (CLO — Course Learning Outcome) กับผลลัพธ์การเรียนรู้ระดับหลักสูตร (PLO — Program Learning Outcome) เพื่อใช้ในการประกันคุณภาพและจัดทำ มคอ. ปัจจุบันการติ๊ก/จับคู่ทำด้วยมือ ใช้เวลานาน และมักพบว่าบาง CLO ไม่มีหลักฐานรองรับจนใกล้สิ้นภาคการศึกษา **ALIGN** จึงถูกออกแบบให้อาจารย์บันทึกการสอนตามปกติ แล้วให้ระบบประมวลผล (AI) จับคู่กับ CLO/PLO และแจ้งเตือนช่องว่างโดยอัตโนมัติ

### สาเหตุราก (Root Cause Analysis — 5 Whys)

- **อาการตั้งต้น**: ผู้สอนไม่ทราบว่าการสอนสอดคล้องกับ course syllabus/CLO ของวิชา และ CLO ของวิชาตอบ PLO ของหลักสูตรมากน้อยแค่ไหน ทำให้พัฒนา/ปรับปรุงการเรียนการสอนไม่ตรงจุด ขณะที่ผู้บริหารหลักสูตรก็ไม่ทราบภาพรวมทั้งวิชา/ทั้งเทอมเป็นรูปธรรม ทำให้แนวทางพัฒนาไม่ยึดโยงกับข้อมูล และเสียเวลาในการประกันคุณภาพหลักสูตรที่ต้องอธิบายโดยขาดหลักฐานที่ชัดเจน
- **ทำไม (1)**: เพราะไม่มีระบบชี้วัดความสอดคล้องอย่างเป็นวิทยาศาสตร์ อาศัยประสบการณ์และความสนใจของอาจารย์เป็นรายบุคคล ไม่มีระบบส่วนกลางออกแบบมาให้
- **ทำไม (2)**: เพราะการนำข้อมูลไปใช้หรือไม่ใช้ ไม่มีการตรวจสอบที่ชัดเจนเป็นรูปธรรม งานนี้จึงเป็นงาน "อยากทำก็ทำ ไม่ทำก็ไม่ผิด" ไม่มีใครให้รางวัลหรือลงโทษ ทั้งที่เป็นเรื่องสำคัญที่ถูกถามซ้ำทุกปี
- **ทำไม (3)**: เพราะยังไม่รู้จะเก็บข้อมูลทั้งหมดอย่างไร มหาวิทยาลัย/ส่วนงานที่รับผิดชอบไม่ได้จัดลำดับความสำคัญในภาพรวมไว้ ไม่มีเจ้าภาพ และคิดว่าทำยาก ลงทุนเยอะ
- **Root Cause**: ไม่มีระบบที่สอดคล้องกับความต้องการใช้งานจริง ใช้งานสะดวก และให้ผลการวิเคราะห์ที่ตอบโจทย์ทั้งฝั่งอาจารย์ผู้สอนและฝั่งผู้บริหารหลักสูตร โดยไม่ต้องทำงานเพิ่มมาก — ข้อมูล/ผลวิเคราะห์ต้องนำไปต่อยอดพัฒนาคุณภาพการเรียนการสอนและหลักสูตรได้จริง

## กลุ่มผู้ใช้งาน (User Roles)

- **อาจารย์ผู้สอน (Instructor)** — ป้อนข้อมูลรายวิชา บันทึกการสอน แนบหลักฐาน/ชิ้นงาน
- **ผู้บริหารหลักสูตร (Program Administrator)** — อาจารย์ที่รับผิดชอบหลักสูตร ทำหน้าที่ประสานหลักสูตรและจัดทำรายงานประเมินตนเอง (SAR) โดยดูภาพรวมความสอดคล้องระดับหลักสูตรและดึงเอกสารหลักฐานจากระบบไปใช้ประกอบการจัดทำรายงาน รวมถึง**อนุมัติ/ปฏิเสธบัญชีอาจารย์ผู้สอนที่สมัครใช้งานเอง**ก่อนบัญชีนั้นจะใช้งานระบบได้จริง — **ไม่ใช่** งานประกันคุณภาพ (QA)

> หมายเหตุ: **งานประกันคุณภาพ (QA)** เป็นผู้ตรวจสอบ/ประเมินผลจากรายงานที่ผู้บริหารหลักสูตรจัดทำ **อยู่นอกขอบเขตของระบบ ALIGN** — ไม่มี login และไม่ใช้ระบบโดยตรง ได้รับเฉพาะเอกสาร/รายงานที่ส่งออกจากระบบเท่านั้น

## ขอบเขต (Scope)

**สิ่งที่ทำ (In Scope)**
- อาจารย์ผู้สอนสมัครใช้งานระบบได้เอง (self-service registration) โดยกรอกข้อมูลตนเอง — บัญชีต้องรอการอนุมัติจากผู้บริหารหลักสูตรก่อน จึงจะใช้งานฟีเจอร์อื่นของระบบได้จริง (ดู E6, กฎทางธุรกิจ #6)
- ป้อนข้อมูล: ประมวลรายวิชา course syllabus รายวิชา, CLO ของรายวิชา และ PLO  ของหลักสูตรโดยแยกออกเป็น สองกลุ่ม คือหลักสูตร 2565  และหลักสูตร 2570  เนื่องจากเป็นหลักสูตรใหม่ กับเก่าที่ยังใช้อยู่  PLO and CLO  อาจมีความแตกต่างกัน พร้อมผูกความสัมพันธ์เบื้องต้น — PLO และรายชื่อวิชาจริงของทั้งสองหลักสูตรอยู่ที่ [[plo-course-master-data|plo-course-master-data]] ใช้เป็นข้อมูลตั้งต้นสำหรับ E1 (AB-01, AB-02)
- บันทึกการสอน (หัวข้อ + แนบชิ้นงาน/หลักฐาน) หลังการสอนจริง  แทนการติ๊กด้วยมือ
- AI ประมวลผลข้อมูลการสอน จับคู่กับ CLO โดยอัตโนมัติ พร้อมค่าความตรง (match %) และเชื่อมโยงต่อไปยัง PLO ที่เกี่ยวข้อง
- แดชบอร์ดหน้าแรก แสดง % ความสอดคล้องรวม รายวิชาที่สอน และแจ้งเตือน CLO ที่ยังไม่มีข้อมูล
- แผนที่ CLO × สัปดาห์ พร้อมจำนวนชิ้นงานสะสมและสถานะเชื่อมโยงถึง PLO
- สรุปรายวิชา: ความสอดคล้อง CLO/PLO, แนวโน้ม (Trends), และจุดที่ควรพัฒนา 3 ระดับ
- ออกเอกสาร Word สำหรับใช้เป็นหลักฐานประกันคุณภาพ/มคอ.

**สิ่งที่ไม่ทำ (Out of Scope)**
- ระบบจัดตารางสอน/ตารางเรียน
- ระบบให้คะแนน/เกรดรายบุคคลของนักศึกษา
- ระบบบริหารจัดการหลักสูตรแบบเต็มรูปแบบ (เช่น การปรับปรุงหลักสูตร มคอ.2)
- บัญชีผู้ใช้/สิทธิ์การเข้าถึงสำหรับงานประกันคุณภาพ (QA) — QA ไม่ใช่ user ของระบบ ALIGN รับเฉพาะเอกสาร/รายงานที่ผู้บริหารหลักสูตรส่งออกจากระบบไปใช้ตรวจสอบภายนอกเท่านั้น

## กฎทางธุรกิจ (Business Rules)

1. ทุกรายวิชาต้องผูก CLO อย่างน้อย 1 ข้อ เข้ากับ PLO อย่างน้อย 1 ข้อ ก่อนจึงจะเริ่มบันทึกการสอนได้  
2. ระบบต้องแจ้งเตือนทันทีที่มี CLO ใดยังไม่มีข้อมูลการสอน/หลักฐานรองรับ (เช่น กรณี CLO 4 ในตัวอย่าง)
3. ผลจับคู่จาก AI (match % และการเชื่อมโยง PLO) เป็นค่าตั้งต้นที่อาจารย์ต้องตรวจสอบและยืนยันได้ก่อนบันทึกจริง (human-in-the-loop) ไม่ใช่ค่าที่บังคับใช้ทันที
4. เอกสารส่งออก (Word) ต้องอ้างอิงเฉพาะชิ้นงาน/หลักฐานที่แนบไว้จริงในระบบเท่านั้น
5. ชิ้นงานของนักศึกษาที่แนบเป็นหลักฐานอาจมีข้อมูลส่วนบุคคลปะปน ต้องจัดเก็บและเข้าถึงตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA) โดยจำกัดสิทธิ์การเข้าถึงเฉพาะอาจารย์ผู้สอนและผู้บริหารหลักสูตรที่เกี่ยวข้อง (งานประกันคุณภาพ/QA ไม่มีสิทธิ์เข้าถึงระบบโดยตรง)
6. บัญชีอาจารย์ผู้สอนที่สมัครเอง (self-service registration) ต้องผ่านการอนุมัติจากผู้บริหารหลักสูตรก่อนเสมอ จึงจะเข้าใช้งานฟีเจอร์อื่นของระบบได้ (ตั้งค่า CLO/PLO, บันทึกการสอน ฯลฯ) — บัญชีที่ยังอยู่ในสถานะ "รออนุมัติ" หรือ "ถูกปฏิเสธ" ต้องไม่สามารถเข้าถึงข้อมูลใดๆ ในระบบได้ไม่ว่ากรณีใด
