# Task Breakdown: ระบบติดตามความสอดคล้อง CLO/PLO (ALIGN)

แตกมาจาก [[../02-plan/product-backlog|product-backlog]] โดยแตก User Story แต่ละข้อ (AB-01 ถึง AB-27) เป็นงานย่อยระดับที่ลงมือทำได้จริง (dev task) ทุกงานยังไม่เริ่มดำเนินการ

หมายเหตุ: งานที่เกี่ยวกับกลุ่มหลักสูตร 2565/2570 (การแยกข้อมูล การ validate ห้ามข้ามกลุ่ม) เป็นประเด็นที่ตัดผ่านหลาย Epic — ดูคอลัมน์ "หมายเหตุ" สำหรับ dependency ระหว่างงาน

หมายเหตุ (อัปเดต): ตาม product-backlog ฉบับล่าสุด — course syllabus เป็นข้อมูลหลักใหม่ (AB-19), สูตร % ความสอดคล้องเปลี่ยนเป็นสัดส่วน CLO ที่แมทช์ต่อ CLO ทั้งหมดของวิชา (AB-20) ร่วมกับค่าความถี่ที่แมทช์ (AB-21), และเพิ่มการวิเคราะห์ gap เทียบ syllabus (AB-22) ที่แสดงผลในแดชบอร์ด (AB-23) — งานที่ผูกกับ AB-08/AB-10/AB-11/AB-16 ถูกปรับปรุงข้อความในตำแหน่งเดิม (คง ID เดิม) ส่วนงานใหม่เริ่มที่ T-064

## หมายเหตุ

- **AB-16 (Area of Improvement — ยืนยันแล้ว, 2026-08-20):** เดิมสเปคเคยระบุว่าเอกสารต้องมีส่วน "จุดที่ควรพัฒนา 3 ระดับ" แต่ไม่มีเอกสารใดนิยามว่า 3 ระดับนั้นคืออะไร ผู้ใช้ได้ยืนยันแล้ว (บันทึกใน [[../../03-testing/01-test-plan/test-plan-align|test-plan-align]] §6.3 และ product-backlog AB-16) ว่า**ไม่มี "3 ระดับ"** — เปลี่ยนเป็น**คำบรรยายข้อความอิสระ (free-text)** ที่อธิบายว่าควรพัฒนาอะไร/ประเด็นอะไรบ้าง ไม่มีระดับ/หมวดหมู่ตายตัว T-056/T-057 ปรับให้สอดคล้องกับข้อยืนยันนี้แล้ว
- **AB-18 (ตัดออกแล้ว, 2026-08-20):** เดิม (ดูบันทึกใน [[../../05-log/2026-08-02-log|05-log]]) มีข้อสังเกตว่า AB-18 เป็น story ที่ทีมวิเคราะห์ backlog อนุมานเพิ่มเติม ไม่ได้ระบุตรงในสเปคต้นฉบับ — ผู้ใช้ยืนยันแล้วว่าไม่ต้องการฟีเจอร์นี้ จึงตัด AB-18 ออกจาก backlog และย้าย task T-062/T-063 ไปที่ [[../../00-archived/backlog-ab-18-area-of-improvement-toggle|00-archived]] เอกสาร Word export แสดง Area of Improvement เสมอ ไม่มี toggle ให้เลือกอีกต่อไป
- **AB-21 (นิยาม "ความถี่ที่แมทช์"):** backlog ระบุว่านับ "จำนวนครั้งที่แต่ละ CLO ถูกจับคู่กับข้อมูลการสอน/หลักฐานตลอดภาคการศึกษา" แต่สเปคต้นฉบับไม่ได้ระบุหน่วยวัดที่ชัดเจนว่านับต่อครั้งที่บันทึก teaching_log (raw count), ต่อสัปดาห์การสอน, หรือเป็นอัตราส่วนเทียบกับจำนวนครั้งที่สอนทั้งหมดในวิชา และไม่ได้ระบุสูตรที่แน่นอนว่าค่าความถี่นี้ "ประกอบกับ" สัดส่วน % (T-073) อย่างไร (เช่น ถ่วงน้ำหนัก, ตัวคูณ, หรือแสดงคู่กันแบบไม่รวมเป็นตัวเลขเดียว) — T-071–T-074 จึงระบุไว้กว้างๆ ตามคำในสเปค ต้องยืนยันหน่วยวัดและสูตรที่แน่นอนกับผู้ใช้ก่อนลงมือ implement จริง
- **AB-19/AB-22 (โครงสร้างข้อมูล course syllabus):** สเปค/backlog ยังไม่ระบุรูปแบบเก็บ "หัวข้อ" ใน course syllabus อย่างชัดเจน (ข้อความอิสระแบบเดียว vs. รายการหัวข้อแบบมีโครงสร้างต่อสัปดาห์/ต่อครั้ง) ซึ่งมีผลต่อการออกแบบ schema (T-064) และความแม่นยำของการเทียบ gap โดย AI (T-075) — ควรยืนยันรูปแบบที่ต้องการกับผู้ใช้ก่อนออกแบบละเอียด
- **AB-24 (ฟิลด์ฟอร์มสมัครสมาชิก — ยืนยันแล้ว, 2026-08-20):** เดิม T-082–T-084 อ้างชุดฟิลด์จาก [[../../02-design/01-prototypes/align-interactive-prototype|align-interactive-prototype]] (M-SignUp.dc.html) ที่มีฟิลด์ "สังกัด/ภาควิชา" รวมอยู่ด้วย ซึ่งยังเป็นข้อสมมติที่ไม่ได้ยืนยัน ผู้ใช้ได้ยืนยันแล้ว (ดู `align-technical-design.md` §2.12 และ `product-backlog.md` AB-24) ว่าฟอร์มสมัครสมาชิกมีเฉพาะ **ชื่อ, อีเมล, รหัสผ่าน** เท่านั้น — **ไม่มีฟิลด์ department/สังกัด** เพราะระบบให้บริการเฉพาะสาขา New Media Communication สาขาเดียว การระบุสังกัดจึงไม่มีความหมาย T-082–T-084 ปรับให้สอดคล้องกับข้อยืนยันนี้แล้ว
