# Prototype: Connected Mobile Walkthrough — ALIGN (ทั้ง 2 บทบาท)

เอกสารนี้อธิบายต้นแบบเสริม **`align-connected-mobile-prototype.html`** (ไฟล์เดียวจบ เปิดตรงในเบราว์เซอร์ได้ทันที ไม่ต้องมี server) — สร้างขึ้นเพื่อแก้ข้อจำกัดของ [[align-interactive-prototype|align-interactive-prototype]] (canvas): **แต่ละ artboard ใน canvas รันแยกกันเป็น sandbox คนละตัว ไม่มีการนำทางข้ามหน้าจอจริง** จึงใช้ทดสอบ flow ต่อเนื่องแบบให้อาจารย์คนหนึ่งเดินตั้งแต่ต้นจนจบไม่ได้

ไฟล์นี้เขียนเป็น single-page app (HTML+CSS+JS ล้วน ไม่มี dependency ภายนอก) ที่**ทุกหน้าจอเชื่อมกันจริงด้วยการนำทางจริง** เหมาะสำหรับให้อาจารย์/ผู้บริหารหลักสูตรทดสอบ UX แบบครบวงจรจริง — ไม่ใช่ตัวแทนของเอกสารข้อความ ([[align-app-screens|align-app-screens]], [[align-program-admin-screens|align-program-admin-screens]]) ที่ยังเป็น source of truth หลักด้าน layout/component/state ตามเดิม ไฟล์นี้เป็นแค่การนำสเปคเดียวกันไปประกอบเป็นต้นแบบที่ทดสอบ flow ต่อเนื่องได้จริง

## วิธีเปิด

ดับเบิลคลิกไฟล์ `align-connected-mobile-prototype.html` ในโฟลเดอร์นี้ เปิดในเบราว์เซอร์ได้ทันที (มือถือหรือคอมพิวเตอร์ก็ได้ — layout ปรับตามขนาดหน้าจอ)

## Flow ที่ทดสอบได้ครบวงจร

1. **สมัครสมาชิก** (AB-24) — กรอกฟอร์มจริง มี validation
2. **หน้ารออนุมัติ** (AB-25, AB-27) — ฟีเจอร์อื่นทั้งหมดถูกล็อก
3. แถบ "สาธิต" ด้านบนสลับเป็น **ผู้บริหารหลักสูตร** → แท็บ "บัญชี" → กด **อนุมัติ**/ปฏิเสธ บัญชีที่สมัคร (AB-26)
4. สลับกลับเป็น **อาจารย์ผู้สอน** → ถ้าอนุมัติแล้ว ปลดล็อกทันที → เดินหน้าจอครบ: แดชบอร์ด → รายวิชา → CLO/PLO → Syllabus → บันทึกการสอน → ตรวจสอบผล AI (Draft→Confirmed จริง) → CLO×สัปดาห์ → สรุปวิชา → ออกเอกสาร Word
5. ฝั่งผู้บริหารหลักสูตร: แดชบอร์ดหลักสูตร, ภาพรวมรายวิชา, ตั้งค่า PLO, SAR, Log การเข้าถึงหลักฐาน, อนุมัติบัญชี

## กรอกข้อมูลได้จริง (ไม่ใช่แค่ static mockup)

**อัปเดต (2026-08-20)**: จุดเหล่านี้ผูกกับ state จริงแล้ว กรอก/เพิ่ม/ลบ แล้วตัวเลขอื่นในแอปคำนวณใหม่ทันที:

- **รายวิชาของฉัน**: "+ เพิ่มรายวิชา" — กรอกชื่อวิชา + เลือกกลุ่มหลักสูตร (2565/2570) แล้วบันทึกเป็นวิชาใหม่จริง
- **CLO & PLO**: "+ เพิ่ม CLO" — พิมพ์คำอธิบาย CLO แล้วแตะเลือก PLO ที่จะผูก (เลือกได้หลายข้อ) ระบบไม่ให้บันทึกถ้ายังไม่ผูก PLO เลย (กฎทางธุรกิจ #1) — วิชาที่ยังไม่มี CLO จะบล็อกไม่ให้เข้าหน้า "บันทึกการสอน" พร้อมข้อความอธิบายเหตุผล
- **Course Syllabus**: "+ เพิ่มหัวข้อ" — กรอกสัปดาห์ที่สอน + หัวข้อ เรียงตามสัปดาห์อัตโนมัติ ลบรายการได้
- **บันทึกการสอน**: เลือก CLO ที่เกี่ยวข้อง, กรอกสัปดาห์/หัวข้อ/วันที่สอนจริง, แนบชื่อไฟล์หลักฐานได้หลายไฟล์ (ลบออกได้) — กดบันทึกแล้วระบบจำลองผล AI (สุ่มค่าความมั่นใจ 35–70%) เป็น draft ส่งไปหน้าตรวจสอบผล AI ทันที
- **ตรวจสอบผล AI**: ทุกผลที่เป็น draft แก้ไข %/ยืนยัน/ปฏิเสธได้จริง — ยืนยันแล้วเท่านั้นที่จะถูกนับเข้า % ความสอดคล้องของวิชา, CLO×สัปดาห์, และ Area of Improvement (Draft→Confirmed ตาม UX Rule 1)
- **ตั้งค่าหลักสูตร/PLO** (ฝั่งผู้บริหารหลักสูตร): สลับแท็บ 2565/2570 ได้จริง, "+ เพิ่ม PLO" ต่อกลุ่มหลักสูตรแยกกัน, ลบ PLO ได้
- แดชบอร์ด/สรุปวิชา/แดชบอร์ดหลักสูตร/ภาพรวมรายวิชา ทุกตัวเลข (%, จำนวน CLO ที่ยังไม่มีหลักฐาน, วิชาพร้อมใช้งาน) **คำนวณจากข้อมูลที่กรอกจริงแบบสด** ไม่ใช่ค่าคงที่อีกต่อไป

## ข้อจำกัด

- ข้อมูลอยู่ใน memory ของหน้าเว็บเท่านั้น (ไม่มี backend จริง) — ปิด/เปิดหน้าใหม่แล้วข้อมูลรีเซ็ตกลับไปเป็นชุดตัวอย่างเริ่มต้น
- แถบ "สาธิต" สำหรับสลับบทบาทเป็นเครื่องมือทดสอบ ไม่ใช่ฟีเจอร์จริงของระบบ (ระบบจริงแต่ละบทบาทต้อง login คนละบัญชี)
- ฟิลด์ฟอร์มสมัครสมาชิก (ชื่อ, อีเมล, รหัสผ่าน) — **[ยืนยันแล้ว]** ไม่มีฟิลด์สังกัด/ภาควิชา เพราะระบบให้บริการเฉพาะสาขา New Media Communication สาขาเดียว
- "ผล AI" เป็นการสุ่มค่าความมั่นใจอย่างง่าย (ไม่ใช่ NLP/AI จริง) และการจับคู่ CLO เลือกโดยผู้ใช้เองตอนกรอกฟอร์ม (ของจริงระบบจะเดา CLO ให้อัตโนมัติจากเนื้อหา) — จำลองไว้เพื่อสาธิต flow ยืนยัน/แก้ไข/ปฏิเสธ (กฎทางธุรกิจ #3) เป็นหลัก ไม่ใช่ความแม่นยำของการจับคู่
