# Prototype: User Flow / Navigation Flow — ALIGN (ทั้ง 2 บทบาท)

แผนภาพลำดับการไปมาระหว่างหน้าจอของแต่ละบทบาท ต่อยอดจากรายละเอียดหน้าจอใน [[align-app-screens|align-app-screens]] (อาจารย์ผู้สอน) และ [[align-program-admin-screens|align-program-admin-screens]] (ผู้บริหารหลักสูตร) — อ้างอิงโทเค็น/component จาก [[../../../DESIGN.md|DESIGN.md]] เช่นเดิม ไม่ทำซ้ำรายละเอียด layout ที่นี่ เอกสารนี้โฟกัสเฉพาะ **ทิศทางการไปมา (edges)** ระหว่างหน้าจอ

ระบบมี 2 บทบาทแยกขาดจากกัน (login คนละ role, เมนูคนละชุด) — ไม่มีหน้าจอ "สลับบทบาท" ในแอป (`CLAUDE.md`) จึงแยกแผนภาพเป็น 2 ชุด ไม่ปนกัน

---

## 0. Entry Gate — สมัครสมาชิก/รออนุมัติ (ก่อนเข้า flow หลักของอาจารย์ผู้สอน)

หมายเลขหน้าจออ้างอิงตาม [[align-app-screens|align-app-screens]] — flow นี้**มาก่อน**หน้าจอ 1 เสมอ และเป็น **gate** ตามกฎทางธุรกิจ #6 (AB-24/AB-25/AB-27): บัญชีที่ยังไม่ผ่านการอนุมัติต้องไม่ถูกพาเข้าสู่หน้าจอ 1 หรือฟีเจอร์อื่นของระบบไม่ว่ากรณีใด

```
[ยังไม่มีบัญชี]
       │
       ▼
┌───────────────────────┐   ส่งฟอร์มสำเร็จ    ┌──────────────────────────────┐
│ 0A. สมัครใช้งาน           │──────────────────►│ 0B. สถานะบัญชี / รอการอนุมัติ    │
│    (Sign Up)             │                    │     (Account Status)          │
└───────────────────────┘                       └───────────┬───────┬──────────┘
       ▲                                                    │       │
       │ ปุ่ม "สมัครสมาชิกใหม่"                 (pending)      │       │ (rejected)
       └────────────────────────────────────────────────────┘       │
                                                                      │
                    ┌─────────────────────────────────────────────────┘
                    │ ค้างที่หน้าจอ 0B (ไม่มีทางลัดไปหน้าอื่น)
                    ▼
        รอผู้บริหารหลักสูตรอนุมัติ/ปฏิเสธที่
        [[align-program-admin-screens#หน้าจอ 6 — อนุมัติบัญชีผู้ใช้ (Account Approval Queue)|align-program-admin-screens หน้าจอ 6]]
        (คนละบทบาท ไม่มีลิงก์ในแอปเดียวกัน — ดูหัวข้อ 3)

        เมื่อ account_status → 'approved' แล้ว → เข้าหน้าจอ 0B อีกครั้ง (state = approved)
                    │
                    ▼
        ปุ่ม "เข้าสู่หน้าแรก" ────────► 1. หน้าแรก/แดชบอร์ด (App Shell เต็มรูปแบบ)
```

**หมายเหตุสำคัญ (AB-25)**: การตรวจสอบ `account_status` ต้องเกิดขึ้น**ทุกครั้ง**ที่มีการร้องขอเข้าถึงข้อมูล/ฟีเจอร์ ไม่ใช่ตรวจครั้งเดียวตอน login — หากบัญชีถูกเปลี่ยนเป็น "รออนุมัติ"/"ถูกปฏิเสธ" ระหว่างใช้งาน (เช่น ถูกปฏิเสธย้อนหลัง) ระบบต้องตัดสิทธิ์ทันที ไม่ปล่อยให้ทำงานต่อในหน้าจอ 1–9 (อ้าง `GET /auth/me/account-status` และหมายเหตุบังคับใน [[../02-technical/align-technical-design|align-technical-design]] §2.12/§3)

**เส้นทาง**: `0A (สมัครใช้งาน) → 0B (รออนุมัติ)` → [รอการอนุมัติที่ align-program-admin-screens หน้าจอ 6] → `0B (approved) → 1 (แดชบอร์ด)` — เส้นทางนี้เกิดขึ้น**เพียงครั้งเดียว**ต่อบัญชี (หรือซ้ำเฉพาะกรณีถูกปฏิเสธแล้วสมัครใหม่) ไม่ใช่ทุกครั้งที่ login หลังอนุมัติแล้ว

## 1. Navigation Flow — บทบาทอาจารย์ผู้สอน (Instructor)

หมายเลขหน้าจออ้างอิงตาม [[align-app-screens|align-app-screens]] — เข้าสู่ flow นี้ได้เฉพาะบัญชีที่ผ่านหัวข้อ 0 ข้างต้นแล้ว (`account_status = 'approved'`)

```
                        ┌─────────────────────────┐
                        │  1. หน้าแรก/แดชบอร์ด      │◄────────────────────────┐
                        └───────────┬─────────────┘                          │
          ┌──────────────┬──────────┼───────────────────┐                    │
          │              │          │                   │                    │
          ▼              ▼          ▼                   ▼                    │
┌──────────────────┐ ┌───────────────────┐  ┌───────────────────┐            │
│ 2. รายวิชาของฉัน   │ │ 5. บันทึกการสอน     │  │ 7. แผนที่ CLO×สัปดาห์│            │
│ (list)            │ │ (จาก Gap Alert CTA) │  │ (เลือกวิชาก่อน)      │            │
└─────────┬─────────┘ └──────────┬─────────┘  └──────────┬─────────┘            │
          │                      │                       │                     │
          ▼                      ▼                       │                     │
┌───────────────────────────┐ ┌───────────────────┐      │                     │
│ 3. จัดการรายวิชา:          │ │ 6. ตรวจสอบ/ยืนยัน   │      │                     │
│    CLO & ผูก PLO (แท็บ) ◄─┼─┤    ผล AI (Review    │      │                     │
│    ↕ สลับแท็บ              │ │    Panel)           │      │                     │
│ 4. Course Syllabus (แท็บ)  │ └──────────┬─────────┘      │                     │
└─────────┬─────────────────┘            │                │                     │
          │ (เมื่อ CLO≥1 ผูก PLO≥1 แล้ว)   │ ยืนยันเสร็จ      │                     │
          │ ปลดล็อกปุ่ม "บันทึกการสอน"      │                │                     │
          └───────────────►(หน้าจอ 5)     └───────►(หน้าจอ 1 หรือ 8)             │
                                                            │                     │
          ┌─────────────────────────────────────────────────┘                    │
          ▼                                                                      │
┌───────────────────────┐        ┌───────────────────────┐                       │
│ 8. สรุปรายวิชา          │──────► │ 9. ออกเอกสาร Word       │                       │
│ (Course Summary)       │  modal │ (Export Panel)         │──── ดาวน์โหลดเสร็จ ────┘
└──────────┬─────────────┘        └───────────────────────┘
           │ ถ้ามี draft ค้าง
           ▼
   (กลับไปหน้าจอ 6 เพื่อยืนยันก่อน)
```

**เส้นทางหลัก (happy path) ต้นภาคเรียน — ครั้งแรกที่ใช้งาน**:
`1 (แดชบอร์ด, Empty State) → 2 (รายวิชาของฉัน) → 3 (ป้อน CLO + ผูก PLO) ↔ 4 (ป้อน syllabus) → [ปลดล็อก] → 5 (บันทึกการสอน) → 6 (ยืนยันผล AI) → 1 (แดชบอร์ดอัปเดตค่า)`

**เส้นทางใช้งานประจำ (หลังตั้งค่าเสร็จแล้ว)**:
`1 (แดชบอร์ด) → 5 (บันทึกการสอนหลังคาบเรียน) → 6 (ยืนยันผล AI) → 1` — ทำซ้ำทุกครั้งที่สอน

**เส้นทางปลายภาค (จัดทำหลักฐาน)**:
`1 → 8 (สรุปรายวิชา) → 9 (ออกเอกสาร Word)` หรือ `7 (แผนที่ CLO×สัปดาห์) → 8 → 9`

**Gate สำคัญที่ต้องคงไว้ในทุก flow (กฎทางธุรกิจ #1)**: ปุ่มเข้าหน้าจอ 5 (บันทึกการสอน) ต้อง disable จนกว่าหน้าจอ 3 จะรายงานว่า CLO ≥1 ข้อผูกกับ PLO ≥1 ข้อแล้ว — ห้ามมีเส้นทางใดที่ข้ามเงื่อนไขนี้ไปถึงหน้าจอ 5 ได้โดยตรง

## 2. Navigation Flow — บทบาทผู้บริหารหลักสูตร (Program Administrator)

หมายเลขหน้าจออ้างอิงตาม [[align-program-admin-screens|align-program-admin-screens]]

```
                    ┌───────────────────────────────┐
                    │ 3. แดชบอร์ดภาพรวมหลักสูตร        │  ← หน้า landing หลัง login
                    │    (แยกแท็บ 2565 / 2570)         │
                    └───────┬───────────────┬─────────┘
                            │               │
                 ┌──────────┘               └───────────┐
                 ▼                                       ▼
      ┌────────────────────────┐              ┌────────────────────────┐
      │ 2. ภาพรวมรายวิชา         │              │ 4. ดาวน์โหลดเอกสาร SAR   │
      │    (สถานะตั้งค่า CLO/PLO) │              │    (ต่อรายวิชาใน scope)  │
      └───────────┬─────────────┘              └────────────────────────┘
                  │
                  │ (ดูสถานะเท่านั้น — แก้ไขจริงทำโดยอาจารย์ที่
                  │  align-app-screens หน้าจอ 3, คนละบทบาท)
                  ▼
      ┌────────────────────────┐
      │ 1. ตั้งค่ากลุ่มหลักสูตร    │  ← เข้าได้อิสระจาก Side Navigation เช่นกัน
      │    และ PLO (2565/2570)  │     ไม่ผูกกับลำดับตายตัวจากหน้าจอ 2/3
      └────────────────────────┘

      ┌────────────────────────┐
      │ 5. ประวัติการเข้าถึง      │  ← เข้าได้อิสระจาก Side Navigation
      │    หลักฐาน (Access Log)  │     เป็นหน้าปลายทาง ไม่มีลิงก์ต่อ
      └────────────────────────┘

      ┌────────────────────────┐
      │ 6. อนุมัติบัญชีผู้ใช้      │  ← เข้าได้อิสระจาก Side Navigation "บัญชี"
      │    (Account Approval)   │     (ใหม่ตาม E6/AB-26) — admin-only, เป็นหน้าปลายทาง
      └────────────────────────┘     ผลลัพธ์การกด "อนุมัติ"/"ปฏิเสธ" ที่นี่ ทำให้บัญชีอาจารย์
                                      ผู้สอนที่ align-app-screens หน้าจอ 0B เปลี่ยนสถานะจริง
```

**เส้นทางหลัก (ตั้งค่าหลักสูตรครั้งแรก)**:
`1 (ตั้งค่ากลุ่มหลักสูตร + PLO) → 2 (ตรวจสอบว่าทุกวิชาผูก CLO–PLO ครบหรือยัง)`

**เส้นทางใช้งานประจำระหว่างเทอม**:
`3 (แดชบอร์ดภาพรวม) → 2 (เจาะดูวิชาที่ยังไม่ครบ) → (แจ้งอาจารย์นอกระบบให้ไปทำที่ align-app-screens หน้าจอ 3 — ผู้บริหารหลักสูตรไม่มีสิทธิ์แก้ไข CLO/PLO ของวิชาแทนอาจารย์)`

**เส้นทางปลายภาค/ปลายปี (จัดทำ SAR)**:
`3 (แดชบอร์ดภาพรวม) → 4 (ดาวน์โหลดเอกสารของวิชาที่ตนดูแล) → ส่งต่อ QA ภายนอกระบบด้วยตนเอง (ไม่มี handoff ในแอป เพราะ QA ไม่มี login)`

**เส้นทางตรวจสอบ PDPA (ตามต้องการ ไม่ผูกกับรอบเทอม)**:
`5 (ประวัติการเข้าถึงหลักฐาน)` — เข้าถึงได้ตลอดเวลาจาก Side Navigation ไม่ขึ้นกับหน้าจออื่น

**เส้นทางอนุมัติบัญชีผู้ใช้ใหม่ (ใหม่ตาม E6, ตามต้องการ ไม่ผูกกับรอบเทอม)**:
`6 (อนุมัติบัญชีผู้ใช้)` — เข้าถึงได้ตลอดเวลาจาก Side Navigation "บัญชี" ไม่ขึ้นกับหน้าจออื่น เช่นเดียวกับหน้าจอ 5 — เป็นจุดเดียวที่ทำให้บัญชีอาจารย์ผู้สอนที่ค้างอยู่ที่ [[align-app-screens#หน้าจอ 0B — สถานะบัญชี / รอการอนุมัติ (Account Status / Pending Approval)|align-app-screens หน้าจอ 0B]] หลุดออกไปใช้งานฟีเจอร์อื่นของระบบได้จริง (ดูหัวข้อ 0 ด้านบนและหัวข้อ 3 ด้านล่าง)

## 3. จุดตัดระหว่าง 2 บทบาท (Cross-role touchpoint — ไม่ใช่ navigation ในแอปเดียวกัน)

ทั้งสองบทบาท**ไม่ได้คลิกลิงก์ข้ามหากันในแอป** (คนละ account, คนละสิทธิ์) แต่มีจุดที่ข้อมูลไหลถึงกันซึ่งควรรู้ไว้ตอนออกแบบ/ทดสอบ:

| จุดตัด | ฝั่งอาจารย์ผู้สอน | ฝั่งผู้บริหารหลักสูตร |
|---|---|---|
| **การอนุมัติบัญชีผู้ใช้ใหม่ (E6)** | สมัคร/เห็นสถานะบัญชีของตนเองที่ [[align-app-screens|align-app-screens]] หน้าจอ 0A/0B — ถูกล็อกไม่ให้เข้าฟีเจอร์ใดจนกว่าจะอนุมัติ | เห็นรายการรออนุมัติ + บัญชีทั้งหมด และกดอนุมัติ/ปฏิเสธที่ [[align-program-admin-screens|align-program-admin-screens]] หน้าจอ 6 (admin-only visibility) — เป็นจุดเดียวที่เปลี่ยนสถานะบัญชีของอีกฝั่งได้จริง |
| PLO ของหลักสูตร | ใช้ตอนผูก CLO–PLO ที่ [[align-app-screens|align-app-screens]] หน้าจอ 3 (เลือกจากที่มีอยู่แล้ว) | ตั้งค่า/แก้ไขที่ [[align-program-admin-screens|align-program-admin-screens]] หน้าจอ 1 |
| สถานะครบถ้วน CLO–PLO ต่อวิชา | เห็นเป็น badge ที่หน้าจอ 2 (รายวิชาของฉัน) | เห็นภาพรวมทุกวิชาที่หน้าจอ 2 (ภาพรวมรายวิชา) |
| % ความสอดคล้อง / coverage_percent | ยืนยันค่าที่หน้าจอ 6, เห็นสรุปที่หน้าจอ 1/8 | เห็นภาพรวมระดับหลักสูตรที่หน้าจอ 3 (อ่านอย่างเดียว) |
| เอกสาร Word ที่ยืนยันแล้ว | สร้าง/ดาวน์โหลดเองที่หน้าจอ 9 | ดาวน์โหลดของวิชาใน scope ที่หน้าจอ 4 |
| การเข้าถึงไฟล์หลักฐาน | ถูกจำกัดสิทธิ์ตาม PDPA ที่หน้าจอ 5 (Evidence Attachment List) | ตรวจสอบย้อนหลังที่หน้าจอ 5 (Access Log) |
