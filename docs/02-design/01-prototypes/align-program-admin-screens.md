> เอกสารใหม่ — ก่อนหน้านี้ยังไม่มีต้นแบบหน้าจอสำหรับบทบาทนี้เลย เดิม `align-app-screens.md` ครอบคลุมเฉพาะบทบาทอาจารย์ผู้สอนจาก pitch deck ตั้งต้น เอกสารนี้ออกแบบใหม่ทั้งหมดตาม backlog ปัจจุบัน (AB-01, AB-04, AB-07 บางส่วน, AB-14, AB-17) และ `DESIGN.md`

อ้างอิงคู่กับ:
- [[../../../DESIGN.md|DESIGN.md]] — โทเค็นและ component เดียวกับที่ใช้ในบทบาทอาจารย์
- [[../../01-requirements/01-spec/requirement-align|requirement-align]] — นิยามบทบาทผู้บริหารหลักสูตร ("อาจารย์ที่รับผิดชอบหลักสูตร ประสานหลักสูตร และจัดทำ SAR — ไม่ใช่ QA")
- [[../../01-requirements/02-plan/product-backlog|product-backlog]]
- [[../02-technical/align-technical-design|align-technical-design]] — โดยเฉพาะ `program_admin_curriculum_scope` และ `evidence_access_log`

ใช้ **App Shell เดียวกับบทบาทอาจารย์** (App Header เป็น ALIGN wordmark, Content Area, Curriculum Tag ทุกจุด) — ดูรายละเอียดที่ [[align-app-screens#0. โครงหน้าจอร่วม (App Shell) — ใช้ทั้งบทบาทอาจารย์และผู้บริหารหลักสูตร|align-app-screens §0]] เปลี่ยนเฉพาะเมนู Side Navigation ให้ตรงบทบาท:

|---|---|---|
| grid | ภาพรวมหลักสูตร | หน้าจอ 3 — แดชบอร์ดระดับหลักสูตร |
| list-check | ภาพรวมรายวิชา | หน้าจอ 2 — สถานะการตั้งค่ารายวิชา |

> **ขอบเขตสำคัญ**: ทุกหน้าจอในเอกสารนี้ต้องกรองข้อมูลตาม `program_admin_curriculum_scope` ของผู้ใช้ที่ login เสมอ (กฎทางธุรกิจ #5) — ผู้บริหารหลักสูตรอาจดูแลเฉพาะกลุ่ม 2565 หรือ 2570 กลุ่มเดียวก็ได้ ไม่จำเป็นต้องเห็นทั้งสองกลุ่ม และ**ห้ามออกแบบ login/สิทธิ์ให้งาน QA เข้าระบบ** (QA อยู่นอกขอบเขต ALIGN โดยเจตนา — รับเฉพาะเอกสารที่ผู้บริหารหลักสูตรส่งออกจากหน้าจอ 4 เท่านั้น)

## หน้าจอ 1 — ตั้งค่ากลุ่มหลักสูตรและ PLO (Curriculum & PLO Setup)

**Map**: AB-01

**จุดประสงค์**: ตั้งค่ากลุ่มหลักสูตร 2565 และ 2570 พร้อมกำหนด PLO ของแต่ละกลุ่มแยกจากกันโดยสิ้นเชิง ก่อนอาจารย์จะเริ่มป้อน CLO ของรายวิชา (หน้าจอ 3 ในเอกสารบทบาทอาจารย์)

**Layout**:
1. หัวข้อหน้า (`text.h1`) "ตั้งค่ากลุ่มหลักสูตรและ PLO"
2. **แท็บแยก 2 กลุ่มหลักสูตรชัดเจน** — แท็บ "หลักสูตร 2565" (สี active ใช้ `curriculum.2565`) และแท็บ "หลักสูตร 2570" (สี active ใช้ `curriculum.2570`) — **ไม่มี tab "ทั้งสองกลุ่ม" รวมกัน** เพื่อป้องกันการกรอก/แก้ไขข้ามกลุ่มโดยไม่ตั้งใจ (AC: "แก้ไข/เพิ่ม PLO ของกลุ่มหนึ่งไม่กระทบอีกกลุ่ม")
3. ภายในแต่ละแท็บ: รายการ PLO เป็นการ์ด (รหัส PLO ด้วย `IBM Plex Mono` + คำอธิบาย) พร้อมปุ่มแก้ไข/ลบต่อรายการ และปุ่ม "เพิ่ม PLO" ท้ายรายการ
4. Curriculum Tag ของแท็บที่กำลังเปิดอยู่แสดงซ้ำที่หัวรายการ (ย้ำภาพว่าอยู่ในกลุ่มไหน แม้สีแท็บจะสื่อไปแล้วก็ตาม — กันความสับสนตาม UX Rule 2 ที่ต้องระบุชัดทุกจุด ไม่ใช่พึ่งสีอย่างเดียว เพราะ WCAG contrast ในโทนเอิร์ธโทนต่ำกว่าสีสด)

**Curriculum tag**: เป็นแกนหลักของทั้งหน้า (แท็บ + tag ซ้ำ) — บังคับสุด (UX Rule 2)

**States**: Empty State ต่อแท็บ (กลุ่มหลักสูตรที่ยังไม่มี PLO เลย — ข้อความ "หลักสูตร 2570 ยังไม่มี PLO — เริ่มเพิ่ม PLO ข้อแรก")

**จุดเชื่อมต่อ**: เข้าจาก Side Navigation "ตั้งค่าหลักสูตร/PLO" — เป็น prerequisite ทางข้อมูลของหน้าจอ 3 (CLO & ผูก PLO) ในเอกสารบทบาทอาจารย์ แต่ไม่ใช่ navigation ต่อกันโดยตรง (คนละบทบาท)

## หน้าจอ 2 — ภาพรวมรายวิชาแยกตามกลุ่มหลักสูตร (Course Setup Status Overview)

**Map**: AB-04

**จุดประสงค์**: ตรวจสอบว่าทุกรายวิชาในแต่ละกลุ่มหลักสูตรตั้งค่า CLO/PLO ครบถ้วนหรือยัง ก่อนเปิดให้อาจารย์ใช้งานจริง (บันทึกการสอน)

**Layout**:
1. หัวข้อหน้า + **ตัวกรอง/แท็บแยกตามกลุ่มหลักสูตร** (เช่นเดียวกับหน้าจอ 1 — `curriculum.2565` / `curriculum.2570`)
2. ตาราง/รายการ Course/Row List Item ต่อวิชาในกลุ่มที่เลือก: รหัส/ชื่อวิชา, อาจารย์ผู้สอน, สถานะความครบถ้วนการผูก CLO–PLO เป็น badge:
   - "พร้อมใช้งาน" — เส้นทึบ `status.confirmed`
   - "ยังไม่ครบ" — เส้นประ `status.draft` พร้อมระบุจำนวน CLO ที่ยังไม่ได้ผูก PLO
3. แถวสรุปด้านบนตาราง: Stat Tile ย่อยแสดงสัดส่วน "N/ทั้งหมด วิชาพร้อมใช้งานในกลุ่มนี้"

**Curriculum tag**: กำกับทุกแถว + ที่ตัวกรอง (UX Rule 2)

**States**: กลุ่มหลักสูตรที่ยังไม่มีรายวิชาเลย (Empty State), กลุ่มที่มีรายวิชาครบทุกวิชาแล้ว (ไม่ต้องเน้นพิเศษ แค่ badge confirmed ทั้งหมด ตาม UX Rule 5/6 ไม่ต้องเพิ่มลูกเล่นฉลอง)

**จุดเชื่อมต่อ**: เข้าจาก Side Navigation "ภาพรวมรายวิชา" — เป็นข้อมูล read-only สำหรับผู้บริหารหลักสูตร (การแก้ไข CLO/PLO จริงยังคงทำโดยอาจารย์ผู้สอนที่หน้าจอ 3 ในเอกสารบทบาทอาจารย์ ตามสิทธิ์ที่ backend ผูกกับ `instructor_id`)

## หน้าจอ 3 — แดชบอร์ดภาพรวมหลักสูตร (Program-level Dashboard)

**Map**: AB-14

**จุดประสงค์**: ให้ผู้บริหารหลักสูตรเห็นภาพรวมความสอดคล้องระดับหลักสูตรของทุกรายวิชา แยกกลุ่ม 2565/2570 อย่างเป็นข้อมูลจริง ไม่ต้องรอถามอาจารย์ทีละคน (ตอบ Root Cause ที่ 2 ในสเปค — ผู้บริหารหลักสูตรไม่ทราบภาพรวมทั้งวิชา/ทั้งเทอมเป็นรูปธรรม)

**Layout**:
1. หัวข้อหน้า + **แท็บแยกกลุ่มหลักสูตร** เช่นเดียวกับหน้าจอ 1/2 — ข้อมูลของสองกลุ่ม**ห้ามแสดงปนกันในตัวเลขเดียว** (AC: "แดชบอร์ดระดับหลักสูตรแยกข้อมูล/สรุปผลตามกลุ่มหลักสูตรอย่างชัดเจน")
2. Stat Tile ขนาดใหญ่: % ความสอดคล้องเฉลี่ยของกลุ่มหลักสูตรที่เลือก (เฉลี่ยจาก `coverage_percent` ของทุกวิชาในกลุ่ม ที่มาจาก confirmed เท่านั้น)
3. รายการ Course/Row List Item ต่อวิชาในกลุ่มนั้น: Match % Indicator ระดับวิชา (เส้นทึบ confirmed) + จำนวน CLO ที่ยังไม่มีหลักฐาน (ลิงก์ดูรายละเอียดที่หน้าจอ 2)
4. กราฟสรุปแนวโน้มรวมของกลุ่มหลักสูตร (เส้นเรียบง่าย สีเดียว `primary.green` เช่นเดียวกับ Trends ของอาจารย์ในหน้าสรุปวิชา)

**Curriculum tag**: เป็นแกนของทั้งหน้า (UX Rule 2)

**States**: Empty State ต่อกลุ่ม (ยังไม่มีวิชาที่มีข้อมูลยืนยันแล้วเลยในกลุ่มนี้), มีข้อมูลบางส่วน (ปกติระหว่างเทอม)

**Access control**: หน้านี้ต้องตรวจ `program_admin_curriculum_scope` ก่อนแสดงข้อมูล — ถ้าผู้ใช้ไม่มีสิทธิ์ดูแลกลุ่มหลักสูตรใดกลุ่มหนึ่ง ให้ซ่อนแท็บของกลุ่มนั้นทั้งแท็บ (ไม่ใช่แสดงแท็บแล้ว disable เพราะจะ leak การมีอยู่ของข้อมูล — ตาม UX Rule 4/PDPA)

**จุดเชื่อมต่อ**: เข้าจาก Side Navigation "ภาพรวมหลักสูตร" (หน้า landing เริ่มต้นของบทบาทนี้) → ไปหน้าจอ 2 (รายละเอียดสถานะตั้งค่า), หน้าจอ 4 (ดาวน์โหลดเอกสารของวิชานั้น)

## หน้าจอ 4 — ดาวน์โหลดเอกสาร SAR (SAR Export / Document Library)

**Map**: AB-17

**จุดประสงค์**: ให้ผู้บริหารหลักสูตรดาวน์โหลดเอกสารหลักฐานของรายวิชาที่ตนดูแลไปประกอบการจัดทำรายงานประเมินตนเอง (SAR) โดยไม่ต้องให้งานประกันคุณภาพ (QA) เข้าระบบเอง

**Layout**:
1. หัวข้อหน้า + ตัวกรองกลุ่มหลักสูตร (เฉพาะกลุ่มที่อยู่ใน `program_admin_curriculum_scope` ของผู้ใช้เท่านั้น — วิชานอก scope ไม่ปรากฏในรายการเลย ไม่ใช่แสดงแล้ว disable)
2. รายการ Course/Row List Item ต่อวิชา พร้อม Curriculum Tag + ปุ่ม "ดาวน์โหลดเอกสาร" ต่อแถว (ใช้ Word Export Panel component เดียวกับฝั่งอาจารย์ แต่จำกัดเป็น read-only ไม่มี toggle Area of Improvement เพราะเป็นการดาวน์โหลดเอกสารที่อาจารย์สร้าง/ยืนยันไว้แล้ว ไม่ใช่การสร้างใหม่)
3. หมายเหตุท้ายรายการ (`text.caption`): "เอกสารที่ดาวน์โหลดมีข้อมูลกลุ่มหลักสูตร (2565/2570) กำกับไว้ชัดเจน พร้อมนำไปแนบในรายงานประเมินตนเอง (SAR) ได้โดยตรง"

**Curriculum tag**: กำกับทุกแถว (UX Rule 2)

**States**: วิชาที่ยังไม่เคย export เอกสารเลย (ปุ่มเปลี่ยนข้อความเป็น "ยังไม่มีเอกสาร — แจ้งอาจารย์ผู้สอนให้สร้างก่อน" แทนปุ่มดาวน์โหลด — โทนเป็นกลาง ไม่ตำหนิใคร)

**จุดเชื่อมต่อ**: เข้าจาก Side Navigation "เอกสาร SAR" หรือจากหน้าจอ 3 (แถวรายวิชา) — เป็นหน้าสุดท้ายของ flow ผู้บริหารหลักสูตรก่อนส่งเอกสารต่อให้ QA ภายนอกระบบ (ไม่มีหน้าจอใดใน ALIGN ให้ QA เข้าถึง)

## หน้าจอ 5 — ประวัติการเข้าถึงหลักฐาน (Evidence Access Log)

**Map**: AB-07 (ส่วนที่เกี่ยวกับผู้บริหารหลักสูตร/ผู้ดูแลระบบ)

**จุดประสงค์**: ให้ผู้บริหารหลักสูตรตรวจสอบย้อนหลังได้ว่าใครเข้าถึง/ดาวน์โหลดไฟล์หลักฐานของนักศึกษาบ้าง เพื่อยืนยันว่าการเข้าถึงจำกัดเฉพาะผู้มีสิทธิ์ตาม PDPA (สอดคล้อง `evidence_access_log` ในเทคนิคดีไซน์)

**Layout**:
1. หัวข้อหน้า "ประวัติการเข้าถึงหลักฐาน"
2. ตัวกรอง: กลุ่มหลักสูตร, รายวิชา, ช่วงวันที่
3. ตารางรายการ log: วันเวลาที่เข้าถึง, ผู้เข้าถึง (ชื่อ + บทบาท), การกระทำ (ดู/ดาวน์โหลด), รายวิชา + Curriculum Tag — **ไม่แสดงชื่อไฟล์หรือ preview เนื้อหาหลักฐานในตาราง log นี้เอง** (ป้องกัน leak ข้อมูลอ่อนไหวซ้อนอีกชั้นแม้ใน audit view — ตาม UX Rule 4 ที่ระบุห้าม leak ชื่อไฟล์/preview แม้ใน error state ก็ตาม จึงยิ่งต้องระวังในหน้าที่เปิดกว้างกว่าอย่างหน้านี้)
4. ไม่มีปุ่ม export ตารางนี้ออกไปเป็นไฟล์แนบใน SAR (คนละวัตถุประสงค์กับหน้าจอ 4 — หน้านี้เป็นเครื่องมือตรวจสอบภายในเท่านั้น)

**Curriculum tag**: กำกับทุกแถว (UX Rule 2)

**States**: Empty State (ยังไม่มี log ในช่วงที่กรอง), รายการปกติ

**Access control**: แสดงเฉพาะ log ของวิชาที่อยู่ใน `program_admin_curriculum_scope` ของผู้ใช้เท่านั้น

**จุดเชื่อมต่อ**: เข้าจาก Side Navigation "ประวัติการเข้าถึงหลักฐาน" — หน้าจอปลายทาง ไม่มีลิงก์ต่อไปหน้าอื่น (เป็นเครื่องมือตรวจสอบ ไม่ใช่ทางผ่านของ flow งานหลัก)
