# Prototype: User Journey Map — ALIGN (ทั้ง 2 บทบาท)

เอกสารใหม่ — ก่อนหน้านี้ยังไม่มี User Journey Map สำหรับบทบาทใดเลย เนื้อหา "เป้าหมาย/pain point" ในเอกสารนี้ยึดตาม **Root Cause Analysis (5 Whys)** ใน [[../../01-requirements/01-spec/requirement-align#สาเหตุราก (Root Cause Analysis — 5 Whys)|requirement-align §Background]] โดยตรง ส่วน "หลังใช้ ALIGN" อ้างอิงหน้าจอจริงจาก [[align-app-screens|align-app-screens]] และ [[align-program-admin-screens|align-program-admin-screens]]

> **อัปเดต (E6)**: เพิ่มขั้นตอน "ก่อนเริ่มใช้งาน — สมัครและรออนุมัติบัญชี" ในตาราง Before/After ของอาจารย์ผู้สอน และขั้นตอน "อนุมัติบัญชีอาจารย์ผู้สอนใหม่" ในตารางของผู้บริหารหลักสูตร ตาม Epic E6 (AB-24 ถึง AB-27) ที่เพิ่งเพิ่มหน้าจอรองรับใน [[align-app-screens|align-app-screens]] และ [[align-program-admin-screens|align-program-admin-screens]] — Root Cause Analysis เดิมในสเปคไม่ได้พูดถึงประเด็นการสมัคร/อนุมัติบัญชีโดยตรง (โฟกัสที่ CLO/PLO/หลักฐาน) แต่ขั้นตอนนี้จำเป็นต้องมีเพื่อให้กฎทางธุรกิจ #6 มีผลจริงก่อนอาจารย์จะเข้าถึงขั้นตอนอื่นในตารางได้เลย

## 1. User Journey Map — อาจารย์ผู้สอน (Instructor)

### เป้าหมายและ Pain Point (จาก Root Cause Analysis)

- **อาการตั้งต้น**: ผู้สอนไม่ทราบว่าการสอนสอดคล้องกับ course syllabus/CLO ของวิชา และ CLO ตอบ PLO มากน้อยแค่ไหน — พัฒนา/ปรับปรุงการสอนไม่ตรงจุด
- **ทำไม (1)**: ไม่มีระบบชี้วัดความสอดคล้องอย่างเป็นวิทยาศาสตร์ อาศัยประสบการณ์/ความสนใจส่วนบุคคล
- **ทำไม (2)**: การนำข้อมูลไปใช้หรือไม่ใช้ไม่มีการตรวจสอบชัดเจน กลายเป็นงาน "อยากทำก็ทำ ไม่ทำก็ไม่ผิด"
- **ทำไม (3)**: ไม่รู้จะเก็บข้อมูลทั้งหมดอย่างไร คิดว่าทำยาก ลงทุนเยอะ
- **เป้าหมายของอาจารย์**: บันทึกการสอนตามปกติหลังสอนจริง แล้วรู้ทันทีว่าตรงกับ CLO/PLO/syllabus แค่ไหน โดยไม่ต้องเพิ่มงานทำมาก และไม่ต้องรอจนใกล้สิ้นภาคการศึกษาจึงรู้ว่า CLO ไหนขาดหลักฐาน

### สรุปคุณค่าที่ ALIGN ส่งมอบให้อาจารย์
เปลี่ยนจาก "รู้ตัวว่าขาดหลักฐานตอนสิ้นเทอม" (reactive, สายเกินแก้) เป็น "เห็นสถานะและ gap ได้ทันทีตลอดเทอม" (proactive) โดยไม่เพิ่มภาระงานป้อนข้อมูลซ้ำซ้อน — อาจารย์ยังคง "บันทึกการสอนตามปกติ" เท่านั้น ระบบเป็นผู้ประมวลผลให้ (ตรงกับหลักการออกแบบ "สะท้อนปัญญา" ใน `DESIGN.md` §1.1)

## 2. User Journey Map — ผู้บริหารหลักสูตร (Program Administrator)

### เป้าหมายและ Pain Point (จาก Root Cause Analysis)

- **อาการตั้งต้น**: ผู้บริหารหลักสูตรไม่ทราบภาพรวมทั้งวิชา/ทั้งเทอมเป็นรูปธรรม ทำให้แนวทางพัฒนาหลักสูตรไม่ยึดโยงกับข้อมูล และเสียเวลาในการประกันคุณภาพหลักสูตรที่ต้องอธิบายโดยขาดหลักฐานที่ชัดเจน
- **ทำไม (2)**: งานติดตามความสอดคล้องเป็นงาน "อยากทำก็ทำ ไม่ทำก็ไม่ผิด" ไม่มีใครให้รางวัล/ลงโทษ ทั้งที่ถูกถามซ้ำทุกปีตอน QA
- **ทำไม (3)**: มหาวิทยาลัย/ส่วนงานที่รับผิดชอบไม่ได้จัดลำดับความสำคัญไว้ ไม่มีเจ้าภาพเก็บข้อมูลรวมศูนย์
- **เป้าหมายของผู้บริหารหลักสูตร**: เห็นภาพรวมความสอดคล้องทั้งหลักสูตร (แยก 2565/2570 ให้ถูกต้อง) แบบมีข้อมูลรองรับจริง เพื่อวางแผนพัฒนาหลักสูตรได้ตรงจุด และจัดทำรายงานประเมินตนเอง (SAR) ได้รวดเร็วโดยไม่ต้องรวบรวมหลักฐานจากอาจารย์แต่ละคนเองทีละราย

### Before ALIGN vs After ALIGN

| ช่วงเวลา/ขั้นตอน | ก่อนมี ALIGN (Pain Point) | หลังมี ALIGN (ช่วยอย่างไร) | หน้าจอ/Touchpoint |
|---|---|---|---|
| **ต้นปีการศึกษา — ตั้งค่าหลักสูตร** | PLO ของหลักสูตร 2565 (เก่า) และ 2570 (ใหม่) กระจัดกระจายในเอกสาร มคอ.2 หลายไฟล์ เสี่ยงใช้ PLO ผิดรุ่นปนกันเวลาตรวจงานอาจารย์ | ตั้งค่ากลุ่มหลักสูตรและ PLO แยกกันชัดเจนในระบบ (แท็บแยก 2565/2570 ไม่ปนกัน) เป็นฐานข้อมูลกลางที่ทุกวิชาต้องอ้างอิง | [[align-program-admin-screens#หน้าจอ 1 — ตั้งค่ากลุ่มหลักสูตรและ PLO (Curriculum & PLO Setup)|หน้าจอ 1]] |

| **ปลายภาค/ปลายปี — จัดทำรายงานประเมินตนเอง (SAR)** | เสียเวลามากในการประกันคุณภาพหลักสูตรที่ต้องอธิบายโดยขาดหลักฐานที่ชัดเจน — ต้องขอเอกสาร/หลักฐานจากอาจารย์แต่ละคนเอง รวบรวมเองด้วยมือก่อนส่ง QA | ดาวน์โหลดเอกสารหลักฐานของรายวิชาที่ตนดูแลได้โดยตรงจากระบบ (เฉพาะข้อมูลที่ยืนยันแล้ว มีกลุ่มหลักสูตรกำกับชัดเจน) นำไปแนบ SAR ต่อได้ทันที โดย QA ไม่ต้องเข้าระบบเอง | [[align-program-admin-screens#หน้าจอ 4 — ดาวน์โหลดเอกสาร SAR (SAR Export / Document Library)|หน้าจอ 4]] |

### สรุปคุณค่าที่ ALIGN ส่งมอบให้ผู้บริหารหลักสูตร
เปลี่ยนจาก "อธิบายคุณภาพหลักสูตรด้วยความรู้สึก/ประสบการณ์ ขาดหลักฐานรองรับ" เป็น "มีข้อมูลที่อาจารย์ยืนยันแล้วรองรับทุกข้อสรุป" — ลดเวลาที่เสียไปกับการประสานงานขอข้อมูล/หลักฐานจากอาจารย์แต่ละคนด้วยมือ โดยยังคง QA ไว้นอกระบบตามขอบเขตที่กำหนด (ผู้บริหารหลักสูตรเป็นผู้ส่งต่อเอกสารเอง ไม่ใช่ให้ QA เข้าระบบ)
