## AB-06 — แนบชิ้นงาน/หลักฐานได้หลายไฟล์ต่อการบันทึกการสอนหนึ่งครั้ง

| ID | ประเภท | Given | When | Then | อ้างอิง |
|---|---|---|---|---|---|
| TC-AB06-01 | Happy path | `U-INSTR-A` กำลังบันทึกการสอนใหม่ให้ `COS101` (ยังไม่กดยืนยัน) | แนบไฟล์ `EV-001.pdf`, `EV-002.docx`, `EV-003.jpg` ต่อเนื่องกัน (รวม 3 ไฟล์) | ระบบรับไฟล์ทั้ง 3 และแสดงรายชื่อไฟล์ทั้งหมดในรายการก่อนกดยืนยันบันทึก | AB-06 AC ข้อ 1, 3 |
| TC-AB06-02 | Happy path | เช่นเดียวกับ TC-AB06-01 (แนบไปแล้ว 3 ไฟล์ ยังไม่ยืนยัน) | ผู้ใช้กดลบ `EV-003.jpg` ที่แนบผิด ก่อนกดยืนยันบันทึก | ไฟล์ `EV-003.jpg` ถูกลบออกจากรายการ เหลือ 2 ไฟล์ (`EV-001.pdf`, `EV-002.docx`) และยังไม่ถูกบันทึกจริงจนกว่าจะกดยืนยัน | AB-06 AC ข้อ 2 |
| TC-AB06-03 | Edge case | `teaching_record` ถูกบันทึกยืนยันไปแล้ว (ไม่ใช่สถานะร่างก่อนบันทึก) | ผู้ใช้พยายามลบไฟล์หลักฐานที่แนบไว้ *หลัง* กดยืนยันบันทึกแล้ว | ระบบไม่อนุญาตให้ลบไฟล์หลังยืนยันบันทึกแล้ว (AC ระบุว่าลบได้ "ก่อนกดยืนยันบันทึก" เท่านั้น) — ป้องกันหลักฐานที่อ้างอิงในเอกสารทางการภายหลังหายไป (เชื่อมกับ BR#4) | AB-06 AC ข้อ 2, BR#4 |
| TC-AB06-04 | Rejection | `U-INSTR-A` กำลังแนบไฟล์ให้บันทึกการสอนของ `COS101` | พยายามแนบไฟล์ประเภท/ขนาดที่ไม่รองรับ (เช่นไฟล์ executable .exe) | ระบบปฏิเสธไฟล์ประเภทนี้ ไม่เพิ่มเข้ารายการไฟล์แนบ | AB-06 AC ข้อ 1 (ป้องกันความเสี่ยงพื้นฐาน) |
| TC-AB06-05 | Edge case | บันทึกการสอนที่มีไฟล์แนบอยู่แล้ว 5 ไฟล์ | ผู้ใช้แนบไฟล์ที่ 6 | ระบบยังรับได้ (AC ระบุ "มากกว่า 1 ไฟล์" ไม่ได้กำหนดเพดานสูงสุด) และแสดงรายชื่อครบทั้ง 6 ไฟล์ | AB-06 AC ข้อ 1, 3 |
| TC-AB06-06 | Happy path (ใหม่ — soft-delete ยืนยันแล้ว) | `U-INSTR-A` กำลังบันทึกการสอนใหม่ให้ `COS101` และแนบไฟล์ `EV-003.jpg` ไว้แล้ว (ยังไม่กดยืนยันบันทึก) | กดลบ `EV-003.jpg` ผ่าน `DELETE /teaching-records/{id}/evidence/{EV-003}` | ระบบตอบสำเร็จ ตั้ง `evidence.is_deleted=true`, `deleted_at=now()` — **ไม่ลบ document/ไฟล์จริงออกจากระบบทันที** (document `evidence` ยังคงอยู่ในฐานข้อมูลเพื่อรักษา audit trail ตาม PDPA) ไฟล์นี้หายไปจากรายการไฟล์แนบที่ใช้งานได้ (Evidence Attachment List หน้าจอ 5) และจะไม่ถูกใช้อ้างอิงเป็นหลักฐานในเอกสาร export ใดๆ อีก | AB-06 AC ข้อ 2, BR#4, align-api-schema-design §3.8/§4.1/§5.1 [ยืนยันแล้ว] |
| TC-AB06-07 | Edge case (ใหม่ — soft-delete ยืนยันแล้ว) | `EV-003.jpg` ถูก soft-delete ไปแล้วตาม TC-AB06-06 (`is_deleted=true`) และยังคงแนบอยู่กับ `teaching_record` ของ `COS101` (สอนโดย `U-INSTR-A`) | `U-INSTR-B` (ไม่ใช่อาจารย์ผู้สอนวิชา `COS101`) พยายามเรียก `GET /evidence/{EV-003}/download` | ระบบยังคงปฏิเสธด้วย HTTP 403 เช่นเดียวกับกรณีที่ไฟล์ยัง `is_deleted=false` — สถานะ soft-delete **ไม่ทำให้การควบคุมสิทธิ์ตาม PDPA อ่อนลง** (ไม่ใช่ "ลบแล้วใครก็เข้าถึงได้ง่ายขึ้น") | AB-06 AC ข้อ 2, AB-07 AC ข้อ 1–2, BR#5, align-api-schema-design §3.8 [ยืนยันแล้ว] |

## AB-07 — จำกัดสิทธิ์เข้าถึงหลักฐานตาม PDPA + audit log

| ID | ประเภท | Given | When | Then | อ้างอิง |
|---|---|---|---|---|---|
| TC-AB07-01 | Happy path | `EV-001.pdf` แนบอยู่กับ `teaching_record` ของ `COS101` ซึ่งสอนโดย `U-INSTR-A` | `U-INSTR-A` เรียก `GET /evidence/{EV-001}/download` | ระบบอนุญาตให้ดาวน์โหลดได้ และเขียน `evidence_access_log` (accessed_by=`U-INSTR-A`, action=download) | AB-07 AC ข้อ 1, 3, BR#5 |
| TC-AB07-02 | Happy path | `U-PA-2565` มี `program_admin_curriculum_scope = [2565]` และ `COS101` อยู่ในกลุ่ม 2565 | `U-PA-2565` เรียกดูหลักฐานของ `COS101` | ระบบอนุญาต เพราะอยู่ใน scope ที่ดูแล และบันทึก log การเข้าถึง | AB-07 AC ข้อ 1, 3 |
| TC-AB07-03 | **Rejection — ไม่มีสิทธิ์ (PDPA)** | `EV-001.pdf` อยู่ใน `COS101` (สอนโดย `U-INSTR-A` เท่านั้น) | `U-INSTR-B` (อาจารย์อีกคนที่ไม่ได้สอน `COS101`) พยายามเรียก `GET /evidence/{EV-001}/download` | ระบบปฏิเสธด้วย HTTP 403 ไม่คืนไฟล์/URL ใดๆ และ**ไม่ leak ชื่อไฟล์หรือ preview** แม้ใน error message (ตาม `DESIGN.md` UX Rule 4) | AB-07 AC ข้อ 1–2, BR#5 |

| TC-AB07-05 | Edge case | มีการเรียกดูหลักฐาน `EV-001.pdf` เกิดขึ้นแล้ว 3 ครั้งโดยผู้ใช้ต่างกัน (`U-INSTR-A` 2 ครั้ง, `U-PA-2565` 1 ครั้ง) | ผู้ดูแลระบบตรวจสอบ `evidence_access_log` ของไฟล์นี้ย้อนหลัง | พบ log ครบ 3 รายการ ระบุผู้เข้าถึง เวลา และ action ถูกต้องครบทุกครั้ง ไม่มีรายการที่ถูกเข้าถึงโดยไม่มีสิทธิ์ปรากฏใน log สำเร็จ (เพราะถูกปฏิเสธไปก่อนถึงขั้นตอนไฟล์จริง) | AB-07 AC ข้อ 3 |
