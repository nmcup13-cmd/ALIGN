# 2026-08-23: วิเคราะห์ Non-Functional Requirements (NFR) และสร้าง `align-nfr.md`

## บริบท

รวบรวม NFR จากกฎทางธุรกิจที่มีอยู่แล้ว (บังคับโดย requirement/backlog/architecture/technical-design) และข้อจำกัดจริงของทีมพัฒนา/งบประมาณที่เพิ่งได้จากการสัมภาษณ์ใน [[../02-design/02-technical/align-tech-stack|align-tech-stack]] (ทีม 1–2 คน, ผู้ดูแลหลัง deploy ไม่ใช่โปรแกรมเมอร์มืออาชีพ, เดดไลน์ปลาย ต.ค. 2569, งบ/data residency ยังไม่ยืนยัน) มาสรุปเป็นเป้าหมายเชิงคุณภาพที่วัดผลได้ — สร้างเอกสารใหม่ [[../02-design/02-technical/align-nfr|align-nfr]] ใน `docs/02-design/02-technical/` (เอกสารที่ 6 ของโฟลเดอร์นี้ ไม่มี subagent เฉพาะทางดูแล เขียนในบทสนทนาหลักตามที่ `CLAUDE.md` ระบุไว้)

## สิ่งที่ยืนยันกับผู้ใช้แล้ว

- **Backup & Disaster Recovery**: ใช้ backup อัตโนมัติของ Supabase free tier เป็นฐาน + เพิ่ม manual/scripted export ก่อนเส้นตายสำคัญทุกรอบ (ก่อนส่งมคอ./SAR)
- **Data & Audit-log Retention (PDPA)**: กำหนดตายตัว **5 ปี** นับจากวันที่บันทึก แล้ว archive/ลบ — ต้องยืนยันตัวเลขนี้ซ้ำกับหน่วยงาน PDPA/ประกันคุณภาพของมหาวิทยาลัยก่อน implement จริง เพราะกระทบ schema ของ `evidence`/`evidence_access_log`
- **Evidence File Size/Type Limit**: สูงสุด 10MB/ไฟล์ เฉพาะ PDF/DOCX/PPTX/รูปภาพ (JPG/PNG)
- **Availability**: ผู้ใช้ตอบ "ไม่แน่ใจ" — ไม่ฟันธง ใช้ default best-effort บน free tier ไปก่อน (portable) ตามแนวทางเดียวกับประเด็นที่ยังไม่ยืนยันใน `align-tech-stack.md` §4 ต้องกลับมาทบทวนเมื่อรู้งบประมาณจริง

## NFR ที่ต้องมี (ไม่มีทางเลือก เพราะสืบจากกฎทางธุรกิจที่บังคับอยู่แล้ว)

Security/Access Control, PDPA/Data Privacy, Maintainability (runbook ก่อน go-live), Auditability (append-only access log), Data Integrity (curriculum isolation), Human-in-the-loop Integrity — ดูรายละเอียด/อ้างอิงกฎที่ [[../02-design/02-technical/align-nfr|align-nfr]] §2

## สิ่งที่เลื่อนออกไปโดยตั้งใจ

Load/performance testing เต็มรูปแบบ, AI precision/recall benchmarking, SSO integration, multi-region/HA infrastructure — เหตุผลอยู่ใน `align-nfr.md` §6 (ส่วนใหญ่สอดคล้องกับขอบเขตที่ `test-plan-align.md` §1 ตัดออกไปแล้วอยู่ก่อนแล้ว ไม่ใช่การตัดใหม่)
