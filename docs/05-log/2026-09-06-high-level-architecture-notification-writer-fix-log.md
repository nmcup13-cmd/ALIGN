# 2026-09-06: ปิด audit finding — ระบุชัดว่า "แกนประสานงาน" เป็นผู้เขียน `notification` ใน align-high-level-architecture.md

## บริบท

การ audit แบบ read-only (`audit-align-docs`) พบข้อขัดแย้งจริงระหว่าง [[../02-design/02-technical/align-high-level-architecture|align-high-level-architecture.md]] §2 กับ [[../02-design/02-technical/align-technical-design|align-technical-design.md]] §2.14:

- §2 (ตาราง logical component) เดิมระบุว่า "กลไกแจ้งเตือนช่องว่างหลักฐาน (Gap Notification Mechanism / GapNotify)" เป็น **read-only ไม่มีสิทธิ์เขียน** เต็มไปหมด
- แต่ §2.14 ของ `align-technical-design.md` (entity `notification` ที่แปลงเป็น Firestore แล้ว) ต้องการการเขียน 2 จุดที่ดูเหมือนเป็นหน้าที่ของกลไกแจ้งเตือนนี้: (1) งานเบื้องหลัง **T-042** ตรวจจับ CLO ที่ไม่มีหลักฐาน แล้ว `set()` แจ้งเตือนใหม่ในทรานแซกชัน query-then-write กันสร้างซ้ำ, (2) กลไก **auto-resolve** ที่ปิดแจ้งเตือน (`is_resolved=true, resolved_at=now()`) ทันทีหลัง `POST /ai-match-results/{id}/confirm` สำเร็จและปิดช่องว่าง CLO นั้น

## การแก้ไขที่ผู้ใช้ยืนยัน (ไม่ใช่การตัดสินใจใหม่ — เป็นการชี้แจงให้ตรงกับสิ่งที่ออกแบบไว้แล้วใน `align-technical-design.md`)

- **GapNotify ยังคง read-only เหมือนเดิมทุกประการ** (least-privilege ตามเจตนาเดิม ไม่ถอย)
- **การเขียนทั้ง 2 จุด (T-042 สร้างแจ้งเตือน + auto-resolve ปิดแจ้งเตือน) เป็นความรับผิดชอบของ "แกนประสานงาน (Core Orchestration)" ทั้งหมด** — T-042 เป็นงานเบื้องหลังฝั่ง backend ของแกนประสานงานเอง ไม่ใช่ส่วนหนึ่งของ component แสดงผล/รายงาน ส่วน auto-resolve เป็น side-effect ที่เกิดในทรานแซกชันเดียวกับการยืนยันผล AI (ซึ่งเป็น write path ของแกนประสานงานอยู่แล้ว) ไม่ใช่การเขียนแยกโดย GapNotify
- ต้นตอของข้อขัดแย้งคือ diagram/ตาราง component เดิม **ไม่เคยระบุเลยว่าใครเป็นผู้เขียน entity `notification`** ไม่ใช่ว่า GapNotify ถูกออกแบบผิดให้มีสิทธิ์เขียน

## สิ่งที่แก้ไขใน `align-high-level-architecture.md`

- **§2 (ตาราง logical component)**: เพิ่มข้อ (5) ในแถว "แกนประสานงาน" ระบุชัดว่าเป็นผู้เขียนแจ้งเตือนช่องว่างหลักฐานเพียงผู้เดียว (ทั้งสร้างจาก T-042 และ auto-resolve) พร้อมปรับคอลัมน์ trust boundary ให้กล่าวถึง entity นี้; ปรับแถว GapNotify ให้คำอธิบายหน้าที่เป็น "อ่านและแสดงผล" ไม่ใช่ "ตรวจจับ" เอง และย้ำ trust boundary ว่าไม่มีสิทธิ์เขียนไม่ว่ากรณีใด
- **เพิ่มหมายเหตุ "[แก้ไข 2026-09-06 — ปิดข้อขัดแย้งที่พบจาก audit]"** ต่อท้ายหมายเหตุความสอดคล้องเดิมใต้ตาราง §2 อธิบายที่มาของข้อขัดแย้งและอ้างอิงจุดที่แก้ไขทั้งหมด
- **เพิ่ม §3.5 (Data Flow ใหม่)**: "CLO ขาดหลักฐาน → เกิดการแจ้งเตือน → แจ้งเตือนปิดอัตโนมัติเมื่อยืนยันผล AI ที่ปิดช่องว่างนั้น" — อธิบายทั้งฝั่งสร้างแจ้งเตือน (แกนประสานงานตรวจจับ+เขียน → GapNotify อ่านมาแสดงที่หน้าจอ 1/7) และฝั่งปิดแจ้งเตือนอัตโนมัติ (ต่อเนื่องจากขั้นตอน 3.1 ข้อ 8–9 การยืนยันผล AI) พร้อม [TRUST BOUNDARY] ย้ำว่า GapNotify ไม่มีเส้นทางเขียนใดๆ เลย — อ้างอิง journey แถว "ระหว่างเทอม — ติดตามความคืบหน้า" และหน้าจอ 1/7 ใน `align-app-screens.md`
- **§4.1 (ตารางหลักการที่สืบมาจากกฎทางธุรกิจ)**: ปรับแถวกฎ #2 ให้ระบุชัดว่าแกนประสานงานเป็นผู้เขียน (ตรวจจับ+สร้าง+auto-resolve) ส่วน GapNotify อ่าน/แสดงผลเท่านั้น ไม่มีสิทธิ์เขียน

ไม่มีการลบเนื้อหาเดิม — เป็นการเพิ่ม/ปรับถ้อยคำให้ชัดเจนขึ้นเท่านั้น (GapNotify read-only ยังคงอยู่ทุกจุดตามเดิม)
